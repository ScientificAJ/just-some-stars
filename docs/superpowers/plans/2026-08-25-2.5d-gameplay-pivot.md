# 2.5D Gameplay Pivot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the unfinished full-3D character/gameplay direction with a validated layered 2.5D runtime, deterministic frame-atlas animation pipeline and one final-quality Mirra proof segment.

**Architecture:** Unity 6 URP uses the 2D Renderer, `Rigidbody2D` gameplay, authored parallax layers and a composition camera. Characters use coherent frame-atlas clips with deterministic metadata and optional bounded synchronized Captain layers; no shipping character depends on a runtime skeleton or FBX rig.

**Tech Stack:** Unity 6 LTS, C#, URP 2D Renderer, Input System, Addressables, uGUI/TextMeshPro, Shader Graph, SpriteRenderer/SpriteAtlas, Python/Pillow tooling, ImageGen-grounded art production, Unity Test Framework and Android CLI builds.

**Spec:** `docs/superpowers/specs/2026-08-25-2.5d-gameplay-pivot-design.md`

## Global Constraints

- Canonical repository and all active assets remain under `/mnt/unity-data/JustSomeStars`.
- `outputs/just-some-stars-2.5d-gameplay-target-v1.png` at SHA-256 `72644970448effd81177222e0aa23ae8a23f9b733077dab6e27e9ca765f5eaed` is the binding gameplay visual target.
- Before Python pipeline work, call
  `codex_app__load_workspace_dependencies` and assign its bundled Python path
  to `JSS_WORKSPACE_PYTHON`; do not guess or use a bare system Python.
- Surface exploration and flight are both true 2.5D; do not restore a free third-person 3D camera.
- Shipping characters use frame atlases, not runtime bones, skin weights, Humanoid avatars or character FBX LODs.
- The Captain has at most five synchronized visual layers. Bespoke crew use flattened atlases where possible.
- Gameplay remains offline-first, purchase-independent and accessible.
- Focused verification runs per stage; full regression, APK and paid device QA run once at Stage 5.
- Preserve unfinished Task 12 3D files until the user separately authorizes archival or deletion.
